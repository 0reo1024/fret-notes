# 演奏練習の苦手箇所ランキングと苦手集中モード — 設計書

作成日: 2026-10-29 ／ 対象の版: 1.0.0（作業ツリーの現状）／ 状態: 1.1.0 で実装済み（実装の記録は docs/migration-progress.md の「1.1.0」節）

実装用のプロンプトは [prompt.md](prompt.md)。

## 1. 目的

演奏練習（単音）で、苦手な「何弦の何フレット（音名）」を記録から見つけ出す。

- 誤った回数と、正しい音を弾くまでの平均時間を組み合わせた**苦手度**で並べる。
- 指板の下に、苦手な順のランキングを表示する。ランキングは**日ごと**に作り、前の日のものも見られるようにする。
- 右側のパネルに「苦手集中」の ON／OFF を追加する。ON のときは、苦手な位置だけを出題する。

### 前提として受け入れる制約

- **音声では弦を判定できない。** 「5弦の C」と出題しても、同じ高さの C を別の弦で弾けば正解になる。そのため、ランキングの「弦・フレット」は**出題した位置**を表し、実際に押さえた位置ではない。このことを画面に1行で書く。
- **オクターブ「自由」では弦を指定しない**（「C を演奏（どのオクターブでも）」）。弦ごとの集計には意味がないため、**自由モードの結果は集計しない**（§4.4）。

## 4. データ設計

### 4.1 記録の単位

既存の itemId（`play:楽器:MIDI`）は**変えない**。理由は次のとおり。

- Leitner の stats、`destinationOf`、`todayMenu`、レベルの判定がこの ID に依存している。
- 回答ごとに `Attempt` をもう1件追加すると、`record()` が日別の回答数と時間を二重に数えてしまう。

そこで、**「日付 × 楽器 × 弦 × フレット × MIDI」の集計**を、Attempt とは別に持つ。保存するのは集計だけで、ランキングは表示のたびに計算する。

```ts
/** One day of single-note practice at one asked position (the string is what was asked, not detected). */
export interface PlayPositionDay {
  date: string;          // localDate（YYYY-MM-DD、端末の日付）
  instrument: ProfileId; // 'guitar' | 'bass4' | 'bass5'
  string: number;        // 1〜弦数
  fret: number;          // 0〜12
  midi: number;          // チューニングの区別に使う（同じ弦・フレットでも、チューニングが違えば別の項目）
  asked: number;         // 出題数（正解した問題＋未回答で終えて記録の対象になった問題）
  answered: number;      // 正解数
  wrong: number;         // 誤りの回数の合計（wrongAttempts の合計。未回答は +1 を加える。§4.3）
  totalMs: number;       // 時間の合計（1問あたり上限あり。§4.3）
}
```

- 項目のキーは `date|instrument|string|fret|midi`。同じキーの項目には加算する。
- チューニングは保存しない。表示するときは、現在のチューニングでその弦・フレットの MIDI を計算し、`midi` が一致する項目だけを使う。こうすると、チューニングを戻せば以前の記録がまた表示される。

### 4.2 保存先（決定）

`TrainingData` に**トップレベルの任意項目 `playPositions: PlayPositionDay[]`** を追加する。

| 案 | 長所 | 短所 | 判断 |
| --- | --- | --- | --- |
| A. トップレベルの新しい項目 | 型と検証を他の記録と同じ水準で書ける。書き出し・読み込み・消去に自然に含まれる | Rust と TS の両方の検証を変える必要がある | **採用** |
| B. `preferences.playWeakDaily` | Rust の変更が不要 | 設定の置き場に大量の記録が入る。`preference()` が毎回 structuredClone する。検証が他と別の流儀になる | 不採用 |

互換性の扱い:

- **Rust（`training.rs`）**: `playPositions` を**任意の項目**として許す。ない場合は7項目、ある場合は8項目になる。ある場合は配列で、長さが上限以内であることを確認する。
  - `FIELDS` の固定長の確認（`object.len() != FIELDS.len()+1`）は、任意項目を数えるように直す。
- **TS（`decodeTrainingData`）**: `playPositions` を任意のキーとして受け付け、ない場合は `[]` を補う。各項目は厳格に検証する（キーの集合、整数、範囲、日付の形式、`answered <= asked`）。
- `emptyTrainingData()` に `playPositions: []` を加える。
- `schemaVersion` は 1 のままにする。古いファイルや書き出したファイルは、そのまま読み込める。新しいファイルを古い版のアプリで読むことはできないが、旧版に戻す運用は想定しない（README に記載する）。

### 4.3 記録する規則

| 出来事 | 記録 |
| --- | --- |
| 正解 | `asked+1`、`answered+1`、`wrong += wrongAttempts`、`totalMs += min(listeningMs, 上限)` |
| 未回答で終えた（「練習を終了」、設定の変更、楽器の変更、苦手集中の切り替えでセッションを作り直したとき） | `wrongAttempts >= 1` または `listeningMs >= 目標時間` の場合だけ記録する。`asked+1`、`wrong += wrongAttempts + 1`、`totalMs += 上限`。すぐにやめただけの問題は数えない |
| 一時停止・タブの切り替え | 記録しない（問題は続いている。再開後に同じ問題を答えると「正解」として記録される） |
| アプリの終了 | 未回答の問題は記録しない（終了処理を複雑にしない） |
| オクターブ「自由」 | 記録しない（§4.4） |

- **1問あたりの時間の上限** = 目標時間 × 3。目標時間は `targetsOf(training.current.preferences).play` で、既定は 4000 ms なので上限は 12 s。ギターを置いて放置した時間で平均が崩れないようにする。
- 未回答で終えた問題は、その位置が分からなかった強い証拠と考える。そのため、誤り1回と時間の上限を加える。

### 4.4 オクターブ「自由」の扱い（決定）

- 自由モードでは**集計しない**。弦を指定していないので、弦ごとの記録として正しくない。
- ランキングの表示は、自由モードでも残す（過去の指定モードの記録を見られる）。見出しの下に「オクターブ自由の結果は弦を指定しないため集計しません」と表示する。
- 苦手集中のスイッチは、自由モードでは**操作できなくする**。注記は「オクターブ指定で使えます」。既存の値（ON）はそのまま保ち、指定モードに戻ると有効になる。

### 4.5 保持と容量

- 上限: `limits.playPositions = 20000` 項目。保持期間は**最新の400日分**の日付までとし、既存の `daily` と同じにする。上限を超えたら古い日付から削る。
- 目安: 1日に30か所 × 400日 ＝ 12,000項目。1項目が約110バイトで、約1.3 MB。学習記録全体の上限（8 MB）に収まる。
- Rust の配列の上限も 20000 にそろえる。

## 5. 苦手度（スコア）

### 5.1 定義

ある位置（その日の集計）について、次のように計算する。

```text
k   = 2                       … 事前の仮想の出題数（データが少ない位置を「ふつう」に寄せる）
e0  = 0.1                     … 事前の誤り率
t0  = 0.6 × 目標時間           … 事前の平均時間
T   = 目標時間（targetsOf(...).play、既定 4000 ms）

誤り率   e = (wrong   + k × e0) / (asked + k)
平均時間 t = (totalMs + k × t0) / (asked + k)

苦手度 = round(100 × ( 0.5 × e / 0.5  +  0.5 × t / T ))
       = round(100 × ( e + 0.5 × t / T ))
```

- 重みは**誤り 50%・時間 50%**。基準は「2問に1回誤る」と「目標時間ちょうど」で、両方がそろうと苦手度 100 になる。
- 苦手度の値の目安:
  - **70以上**を「苦手」として強調する（`weakThreshold = 70`）。
  - 40〜69 は「ふつう」。
  - 39以下は「得意」。
- 定数（`k`、`e0`、`t0` の係数、重み、しきい値）は `weak-positions.ts` の先頭に1か所でまとめて定義する。後で調整しやすくするため。

### 5.2 計算例（目標時間 4000 ms）

| 状況 | asked | wrong | totalMs | e | t | 苦手度 |
| --- | --- | --- | --- | --- | --- | --- |
| 速く正確（10問・平均2.5 s・誤りなし） | 10 | 0 | 25000 | 0.017 | 2483 | **33** |
| 1問だけで、2回誤り・9 s | 1 | 2 | 9000 | 0.733 | 4600 | **131** |
| 5問・誤り3回・平均5 s | 5 | 3 | 25000 | 0.457 | 4257 | **99** |
| 3問・誤りなし・平均6.7 s（遅いだけ） | 3 | 0 | 20000 | 0.04 | 4960 | **66** |
| 1問・誤りなし・2 s | 1 | 0 | 2000 | 0.067 | 2267 | **35** |
| 未回答で終了1問（誤り0） | 1 | 1 | 12000 | 0.4 | 5600 | **110** |

これらはテストの正解表として使う（四捨五入した値で比べる）。

### 5.3 並べ方

1. 苦手度の降順
2. 同じ値なら、`wrong` の降順
3. 次に平均時間（`totalMs / asked`）の降順
4. 最後に、弦の番号・フレットの昇順（並びを決定的にする）

- 出題数が3未満の行には「参考」の印を付ける。順位からは外さない。スムージングによって、データの少ない位置は「ふつう」に寄るためである。

## 6. 日ごとのランキング

- ランキングは**その日（端末の日付、`localDate`）の記録だけ**で作る。
- 練習するたびに、その日のランキングをその場で更新する（正解・未回答の記録が加算されたら、再描画する）。
- 前の日のランキングは、保存されている集計から同じ計算で再現する。スナップショットは保存しない。
- 注意: 目標時間（記録タブの設定）を変えると、過去の日の苦手度も新しい目標で計算し直される。過去の値を固定しないことは README に1行書く。
- その日の記録が少ないと、ランキングが短くなる。これは仕様とし、画面に「この日の記録：N か所・M 問」と表示する。

### 6.1 対象の絞り込み

- 楽器: 表示中の楽器（`instrument`）。
- チューニング: 現在のチューニングで、`(string, fret)` から計算した MIDI が `midi` と一致する項目。
- 出題範囲（弦・フレット・ナチュラル音のみ）では**絞らない**。範囲を変えても、苦手の記録は消えたように見えないほうがよい。

## 7. 苦手集中モード

### 7.1 動作

- **ON** のとき、出題は苦手な位置だけになる。
  - 出題範囲の設定（弦・フレット・ナチュラル音のみ）は使わない。範囲の UI は操作できなくし（`disabled`）、「苦手集中中は出題範囲を使いません」と表示する。範囲の値は変更せず、保存も残す。
- **出題する位置の選び方**（`focusPositions`）:
  1. 各日のランキングから、苦手度が 40 以上で、対応音域（25〜1500 Hz）内の位置を候補とする。
  2. 元にする日: 今日の候補が2件以上あれば今日。なければ、**候補が2件以上ある最新の日**を、さかのぼって探す。現在の楽器・チューニングについて探す。
     - 例: 朝、苦手集中で1問答えると、今日の記録は1か所だけになる。この場合は、昨日の候補（例 8件）を使い続ける。
  3. その日の候補の上位から、最大 N 件を選ぶ。N は 5／10／15 から選び、既定は 10。
  4. どの日にも候補が2件以上なければ、苦手集中は使わず、**通常の出題範囲で出題**する。状態の欄に「苦手の記録が足りないため、通常の範囲で出題しています」と表示する。
- **出題の順序**: 既存の `PerformanceSession` のシャッフルをそのまま使う（1周で各位置を1回ずつ。同じ音が続かない）。`PerformanceSession` 自体は変更しない。
- **出題する位置の固定**: 選んだ一覧は、セッションを作った時点で固定する。練習中に苦手度が変わっても、出題は入れ替えない。次にセッションを作るとき（終了後の再開、設定の変更、スイッチの切り替え）に、選び直す。
  - 選んだ一覧は、画面側の状態 `focusSelection: {date, positions} | null` に保持する。`focusPositions` を呼ぶのは `newSession()` の中だけにする。
  - `targets()`、`canStart()`、`render()` は `focusSelection` を読むだけで、選び直さない。
  - `configurationKey` には、苦手集中の状態・N と、`focusSelection` の日付と位置のキーを**保持している値から**入れる。キーの計算の中で選び直してはいけない。選び直すと、回答で集計が増えるたびにキーが変わり、練習中のセッションが捨てられてしまう。
- 練習中の結果は、通常どおり集計に加算する。苦手集中で練習した日のランキングは、集中した位置が中心になる（仕様）。
- 出題の文言は通常どおりにする（「5弦の C を演奏」）。出題の上に「苦手集中：N か所（YYYY-MM-DD の記録から）」と1行表示する。

### 7.2 保存

- `training.preferences.play` に `{ octave, focus: boolean, focusCount: 5|10|15 }` として保存する。
- **既存の不具合の予防**: 今の `updatePreferences('play', {octave})` は、オブジェクトを丸ごと置き換える。このままでは、オクターブを変えるたびに `focus` が消える。読み込んだ値に変更点を重ねて保存する形（`{...current, octave}`）に直す。
- 読み込みでは、想定外の値を既定値（`focus: false`、`focusCount: 10`）に戻す。

- 置き場所は `.play-board-shell` の直後（`.play-feedback` の前）。
- 日付の切り替え:
  - `‹` と `›` で、記録がある前後の日へ移る。
  - 日付の `<select>` には、記録がある日（新しい順）と今日を並べる。
  - 「今日」ボタンで今日に戻る。
  - 表示中の日付は保存しない。アプリを起動したとき・楽器を変えたときは今日に戻る（タブを切り替えても、選んだ日は保たれる）。
- 行の表示:
  - 苦手度が 70 以上の行は強調する。色だけに頼らず、苦手度の数値の横に「苦手」と文字でも書く。
  - 出題数が3未満の行には「参考」と書く。
  - 音名の表記は、出題範囲の表記設定（`range().notation`）に従う。
- **前回比**（任意・推奨）: 一つ前の記録がある日の順位と比べて、「↑2」「↓1」「新」を表示する。
- 練習中も更新する。描画は回答・記録のたびに行い、毎フレームは行わない。`render()` の中で、キー（日付、楽器、チューニング、集計の件数、合計値）が変わったときだけ DOM を作り直す。
- **指板には苦手の位置を表示しない。** 出題中に表示すると答えになるため。将来の案として §11 に書く。
- アクセシビリティ: 一覧は `<table>` にし、`caption` と `th scope` を付ける。日付の切り替えは `aria-label` 付きのボタンにする。

## 10. テスト

1. **苦手度**: §5.2 の表がすべて一致する。目標時間を 3000 にした場合の例も1件確認する。
2. **集計**
   - 同じキーには加算され、別の日付・楽器・MIDI は別の項目になる。
   - 1問あたりの時間の上限が効く。
   - 400日を超えた日付と、20000件を超えた項目は、古いものから削られる。
3. **未回答の規則**: 誤り0かつ目標時間未満なら記録しない。誤り1以上、または目標時間以上なら `wrong + 1`・上限の時間で記録する。
4. **ランキング**
   - 並べ方（§5.3）の同点の処理。
   - チューニングを変えると、MIDI が一致しない項目が除外される（ドロップD の6弦）。
   - 4弦／5弦ベース。
   - 出題範囲で絞らないこと。
5. **日付**: `rankingDates` が、楽器・チューニングごとに記録のある日だけを新しい順で返す。日付の境界には `localDate` を使う（23:59 と 0:01 の記録が別の日になる）。
6. **苦手集中**
   - 今日の記録がなければ、候補が2件以上ある最新の日から選ぶ。
   - 今日の候補が1件で昨日の候補が8件なら、昨日から選ぶ。
   - 苦手度 40 未満は除く。最大 N 件。
   - どの日にも候補が2件以上なければ null（通常の出題範囲に戻す）。
   - 対応音域外の位置は除く。
   - 画面側: セッションの途中で集計が増えても、`configurationKey` が変わらない（`focusSelection` を固定していることの確認）。
7. **PerformanceSession.pending()**: 聴き取り中・候補中・一時停止中は問題を返し、正解直後・終了後は null を返す。既存の `tests/performance.test.ts` は変更せずに成功する。
8. **検証**
   - `decodeTrainingData` は、`playPositions` がない古いデータを `[]` で補って読む。
   - 不正な項目（負の数、`answered > asked`、未知のキー、日付の形式の誤り、弦・フレットの範囲外）を拒否する。
   - Rust の `validate` は、7項目と8項目の両方を受け付け、上限を超える配列を拒否する。
9. **preferences のマージ**: オクターブを変えても `focus` と `focusCount` が残る（`view` の小さな関数として切り出し、テストする）。

## 11. 範囲外・将来の案

- 指板に苦手の位置を重ねて表示する（練習していないとき、または「答え合わせ」のときだけ）。
- 7日間・30日間の合算ランキング（日ごとの集計があるので、後から追加できる）。
- オクターブ自由モード用の、音名ごとのランキング。
- 記録タブ（`records`）への、苦手な位置の要約の表示。
- 苦手度に応じて出題の頻度に重みを付ける（`weightedDeck` を使い、苦手な位置を1周に2回出すなど）。

## 12. 利用者が判断する事項（この設計で仮に決めたもの）

| 事項 | この設計の決定 | 別の案 |
| --- | --- | --- |
| ランキングの期間 | その日の記録だけ | 直近7日の合算 |
| 苦手度の重み | 誤り 50%・時間 50% | 誤りを重くする（例 70%・30%） |
| 苦手集中の元データ | 今日（候補が2件以上あれば）、なければ候補が2件以上ある最新の日 | 直近7日の合算 |
| 苦手集中と出題範囲 | 範囲を使わない（苦手な位置だけ） | 範囲内の苦手な位置だけ |
| オクターブ自由 | 集計しない。苦手集中も使えない | 音名ごとに別に集計する |
| 未回答で終えた問題 | 誤りか目標時間超えがあれば、誤り＋1・時間の上限で記録する | 記録しない |
