# Part 2：追加すべき機能の一覧

## 2.1 評価の前提

評価の軸は、依頼にあった次の6つです。

- アドリブへの寄与
- 現在の学習レベルとの適合
- 既存機能との重複
- 実装の難しさ
- 技術的な実現性
- 使いやすさ

表の「実現性」は、Part 1 で確認した現在の音声エンジンを前提に判定しています。前提となるエンジンの性質は次のとおりです。

- 単音しか認識できない。
- 発音の立ち上がり（オンセット）を検出しない。
- 音を認識するまでに約200〜450 msかかる。

評価記号: ◎ 高い ／ ○ 中程度 ／ △ 低い・条件付き

## 2.3 統合と再編（推奨する機能構成）

依頼の11機能は、画面単位では**5つの練習**と**3つの共通基盤**にまとめるのがよいと考えます。

```text
共通基盤
  ① 和声エンジン（純粋関数）: コード記号・度数・インターバル・綴り・ダイアトニック・進行
  ② 判定エンジン: 回答方法（選択／音名／指板クリック／演奏）を共通の「正解条件（matcher）」で判定
  ③ 学習記録ストア: 試行の記録 → 項目ごとの統計 → 間隔反復（復習）

練習（画面・タブの単位）
  1. 指板トレーニング（既存の拡張）  … 音名⇔位置、全位置探索、反応時間、演奏で回答
  2. ハーモニー・トレーナー          … A（コードトーン）＋B（インターバル）＋C（アルペジオ）＋Fの知識問題
  3. 進行トレーナー                  … D（コードチェンジ）＋E（ボイスリーディング）＋Fの進行素材＋I（モチーフ）
  4. 耳とリズム                      … H（聴音）＋G（リズム）
  5. 記録                            … K（弱点・定着・今日の練習）
```

統合する理由は次のとおりです。

- **A・B・Cは同じ問いの形をしている。** どれも「基準音と関係を示し、目標の音（列）を答える」問題で、違うのは関係の種類（度数、インターバル、構成音の順番）だけ。共通にすると、回答方法を4種類（選択、名前、クリック、演奏）用意する作業が1回で済む。
- **D・E・Iは同じ「進行の上を時間に沿って進む」仕組みを使う。** ボイスリーディングは「次の音の候補を前の音からの距離で絞り込む」条件を、モチーフは「音の並びの輪郭」の条件を加えたものになる。
- **Fを独立した画面にすると、表を眺めるだけの練習になりやすい。** ダイアトニックとII–V–Iは、次の2つとして使う方が演奏に結び付く。
  - 進行ライブラリの素材（すぐにD・Eで弾ける）
  - ハーモニートレーナーの知識問題（「C メジャーの ii は？」「G7 の機能は？」）

## 2.4 追加の提案（依頼にない機能）

| 提案 | 内容 | 理由 | 優先度 |
| --- | --- | --- | --- |
| **P-1 歌ってから弾く（オーディエーション）** | 出題された音（例: G7 の 3rd）を先に歌い、マイクで音高クラスを判定する。続けてギターで弾く | 頭の中で鳴らす力を育てる（目標8）。既存のYINは声にも使える（25〜1500 Hz）。歌唱は音程が揺れるため、半音単位・音高クラスで判定する | 中（聴音と同時期） |
| **P-2 ターゲットノート着地練習** | 進行に合わせて自由に弾き、**コードが変わった直後の最初の音**がガイドトーン（3rd/7th）かどうかだけを判定する | 自由な即興と客観的な判定を両立できる。音楽性を点数にせず、「着地」という1点だけを測る | 高（Dの第7段階に組み込む） |
| **P-3 制限付き即興** | 「3音だけ」「1弦だけ」「5Fから7Fだけ」「休符を必ず入れる」などの制約を出題し、録音はせずに自己評価する | 自由な即興への足場（Hal Crook 的な制約練習）。実装は軽い | 中 |
| **P-4 ドローン／ルートの持続音** | 選んだルートを持続音で鳴らし、モードの響き（ドリアンの6度など）を体で覚える | モードを「理解して使う」（目標7）ための聴覚の練習。Web Audio の合成で十分 | 中 |
| **P-5 「今日の練習」自動メニュー** | 記録から、復習が必要な項目と弱点を混ぜた10〜15分のメニューを作る | 定着を重視する方針（間隔反復）を、利用者の操作なしで回せる | 中（記録の後） |
| **P-6 ベース向けの着地練習** | 進行に合わせ、1拍目にルート、3拍目に3rd/5thを弾くウォーキングの骨格練習 | ギター・ベース両対応の方針を保つ。Dの判定条件の組み合わせで実現でき、追加の負荷は小さい | 低〜中 |

## 2.5 削除・統合・後回しにするもの

| 対象 | 判断 | 理由 |
| --- | --- | --- |
| 和音（同時に鳴る複数音）の認識 | **設計しない** | 単音のYINでは不可能。和音の判定を前提にした練習は作らない（制約に従う）。ボイシングの練習は、構成音を1音ずつ弾く形にする |
| シェイプの丸暗記を中心とした練習 | **追加しない** | 依頼の方針どおり。既存のシェイプ表示はリファレンスとして残す |
| ジャズスタンダードの曲データ同梱 | **後回し・最小限に** | メロディには著作権がある。コード進行は一般的な型（ii–V–I、ジャズブルース、循環進行など）を同梱し、曲の進行は利用者が入力・保存する |
| アウトサイド・フレージングの自動採点 | **採点しない** | 音楽的に正しい答えが1つに決まらない。理論的な説明と自己評価にとどめる |
| 演奏音声の録音・保存 | **後回し（任意・オプトイン）** | プライバシーと保存容量の問題がある。代わりに「音高と時刻の記録」を合成音で再生する（7章 P-7） |
| 15F以上への指板拡張 | **後回し** | 0〜12Fで、すべての弦の全音高クラスを網羅できる。12F以上は同じ音名のオクターブ上になる。影響範囲が大きい（Part 1 §1.10-3）ため、要望が強くなってから行う |
| スマートフォン・タブレット版 | **別の判断として切り出す** | 現在は Windows 版だけ。設計はタッチ操作と狭い幅を考慮しておくが、移植（Tauri mobile、音声エンジンの検証）は別プロジェクトにする |
