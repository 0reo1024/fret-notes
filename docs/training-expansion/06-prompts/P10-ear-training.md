# P10 聴音・メロディ再現と歌唱モード

あなたは Fret Notes（Tauri 2 + TypeScript + Rust）の開発を担当します。今回は新しい機能タブ「耳・リズム」を作り、最初の出題の種類として**聴音**を実装します。アプリが短いメロディを再生し、利用者がギターで再現します。あわせて、出題された音を先に歌う「歌唱モード」も追加します。

## 目的
- 仕様は `docs/training-expansion/03-feature-specs.md` の §3.7、`07-proposals.md` の P-1（歌ってから弾く）と P-4（ドローン）。
- 音名を覚えているだけでは解けないようにし、音を聴いて再現する力を育てる。

## 最初に確認すること（既存コード）
- P8 の `src/platform/sound.ts`（`playNote`、AudioContext の管理）。
- P2 の `NoteSegmenter`、`SequenceTracker`、音声ハブ。P0 で推奨した最小の安定時間。
- P1 の和声エンジン（調の音階は、既存の `scales` の ionian/aeolian と `spell` で作る）。
- `src/domain/tuner/settings.ts` の `AudioSettings`（入力チャンネル）と、P2 の `mountAudioSettings`。

## 変更対象と要件
1. ドメイン（新規・提案名 `src/domain/training/ear.ts`）
   - `generateMelody(level, key, register, random)`: 生成の規則は次のとおり。
     - 調の音を使う（段階が上がると半音階も使う）。
     - 最初の音は主音またはコードトーン。
     - **同じ MIDI を連続させない。**
     - 跳躍の最大幅は段階で決める。
     - 音域は楽器の範囲の中にする（ベースは低い音域）。
   - 種類: 単音（主音の後に1音）、インターバル（2音。1音目は表示する）、メロディ（2〜8音）、コードトーンのメロディ（指定したコードの構成音だけ）。
   - `staircase(state, correct)`: 階段法。2回続けて正解したら1段上げ、1回誤ったら1段下げる。段階の下限と上限を守る。
   - 項目ID は `ear:<種類>:<音数>:<diatonic|chromatic>`。
2. 再生
   - 調の文脈を作る（任意）。主音のドローン、または I–IV–V–I の和音（合成音を同時に鳴らす）。
   - メロディを再生する。テンポは段階による（例: 1音 600 ms）。
   - 「もう一度聴く」（R キー）。回数の制限はオプションにする。
3. **半二重の判定**
   - 再生している間と、再生が終わってから 300 ms の間は、観測を判定に使わない。証拠を破棄する。
   - その間に利用者が弾き始めた場合は、再生が終わった後の新しい安定音から数える。
   - 案内を表示する: 「マイクで入力している場合は、ヘッドホンを使ってください」。
4. 判定
   - `SequenceTracker` の順番ありで判定する。
   - オクターブの扱い
     - 音高クラスのみ（既定）: 各段階を音高クラスの matcher にする。
     - オクターブも一致: MIDI の matcher にする。
   - 誤りの方針
     - 最初の音を誤ったら、その場で「1音目から」と表示してリセットする（既定）。
     - 最後まで弾いてから比べ、何音目が違うかを示す（編集距離）。
   - 正解の後は、音名・度数・指板の位置を表示し、もう一度再生できるようにする。
5. 歌唱モード（P-1）
   - コードトーン（P5）・聴音・ライン（P9）の各画面に「先に歌う」オプションを付ける。
   - 判定は音高クラスで、許容幅は ±50 セント（最も近い半音に丸める）。安定時間は 300 ms。
   - P2 で、`PerformanceSession` の許容値の検証を「許可された値の集合を引数で渡す」形にしてある場合は、それを使う。そうでなければ、歌唱用の許容値を追加する。**既存の演奏練習の許容値は変えない。**
   - 声とギターを別の入力チャンネルで扱えるようにする。preferences に「歌唱用の入力チャンネル」を保存する。同じ入力を使う場合は、そのまま共有する。
   - 歌って正解した後、ギターで同じ音を弾く段階へ進む（2段階）。
6. ドローン（P-4）
   - 指板学習の「スケール表示」から、ルートの持続音（＋5度）を鳴らせるボタンを追加する。既存の指板学習の画面に小さなボタンを1つ追加するだけにし、既存の表示は変えない。
   - 鳴らしている間は、指板学習以外の入力の判定に影響しない（指板学習は音声入力を使わない）。

## UI・UX 要件
- 出題カードには「♪ 4音」とだけ表示し、音名は隠す。
- 大きな「もう一度聴く」ボタン。進み具合は「●●○○」。
- 再生中は「再生中…」と表示し、その間の入力が判定されないことを示す。

## 音声認識との連携要件
- 判定は音声ハブ → `NoteSegmenter` → `SequenceTracker` の順で行う。
- 半二重の制御は、ハブまたはこの画面の受け手で、観測を捨てる形にする。`AudioController` は変更しない。

## 音楽理論の検証事項
- 生成したメロディの各音が、調の音階（または指定したコードの構成音）に含まれる（段階が半音階でない場合）。
- 綴りは調に従う（E♭ メジャーなら A♭ を G♯ と綴らない）。
- 同じ MIDI が連続しない。音域の外に出ない。

## テスト
- 生成の性質（上記）を、乱数を固定して多数回の試行で確認する。
- `staircase` の上げ下げと境界。
- 半二重: 再生中の観測を判定に使わない。
- 合成した観測列で、3〜4音のメロディの正解・誤り・リセットを確認する。
- 歌唱の許容値が、既存の演奏練習の検証に影響しないこと。
