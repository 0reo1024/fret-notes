# P11 リズムトレーナー（タップ入力）と遅延の補正

あなたは Fret Notes（Tauri 2 + TypeScript + Rust）の開発を担当します。今回は「耳・リズム」タブに**リズム**を追加します。現在の音声エンジンは発音の時刻（オンセット）を取得できないため、まず**タップ入力**（キーボード、画面のタップ、キーボードとして認識されるフットスイッチ）で、リズムを客観的に測る機能を作ります。

## 目的
- 仕様は `docs/training-expansion/03-feature-specs.md` の §3.8（R1）、`04-architecture.md` の §4.5。
- 対象: 4分・8分・16分音符、3連符、休符、シンコペーション、アクセント（表示だけ）、2・4拍のクリック、スウィング、モチーフのリズムの変形。

## 最初に確認すること（既存コード）
- P8 の `src/platform/sound.ts`（スケジューラー、`toPerformanceTime`）と `src/domain/training/timeline.ts`。
- P10 の「耳・リズム」タブの構造。
- P3 の `TrainingRepository`（`calibration.tapOffsetMs` の保存先）。
- 既存のキーボード処理が `e.repeat` を無視していること（`src/features/fretboard-study/view.ts`）。同じ規則にする。

## 変更対象と要件
1. ドメイン（新規・提案名 `src/domain/training/rhythm.ts`）
   - `RhythmPattern {id, name, subdivision: 4|3|6, beats, cells: ('note'|'accent'|'rest')[], swing?}`。
   - `expectedOnsets(pattern, bpm, startMs)`
     - スウィング比（50〜75%）は、8分音符の裏拍だけをずらす。
     - 3連・6連は等分する。
   - `judgeHits(expected, actual, windows = {tight: 35, ok: 70})`
     - 各打点を最も近い予定に一対一で割り当てる（貪欲法ではなく、順序を保った割り当て）。
     - 結果は tight / ok / early / late / extra / missed。
   - `summary(hits)`: 平均のずれ（走る・もたる傾向）、標準偏差（安定性）、正確な打点の割合。
   - パターンのライブラリ
     - 4分
     - 8分
     - 8分の裏だけ
     - 3連
     - 16分
     - 16分の組み合わせ（例: 8分＋16分×2）
     - シンコペーション（例: 1拍目の裏から次の拍にまたぐ）
     - 休符を含むもの
     - チャールストン
   - 変形: 1拍ずらす、倍の長さにする、半分の長さにする（P13 のモチーフと共有する）。
   - 項目ID は `rhy:<パターンid>:<bpm帯>`（bpm帯の例: 60-79）。
2. 遅延の補正
   - 16回のクリックに合わせてタップし、ずれの中央値を `tapOffsetMs` として保存する。外れ値（±150 ms 超）は除外する。
   - 補正をしていない場合は、結果に「未補正」と表示する。
   - 補正値が 150 ms を超えたら、Bluetooth など遅延の大きい出力の可能性を案内する。
3. 画面
   - グリッド表記: 1拍を 4/3/6 分割したマス。音は●、休符は空白、アクセントは大きな●で示す。
   - テンポ、拍子（4/4、3/4）、クリック方式（4拍／2・4拍／1拍目／なし）、スウィング比、繰り返し回数、カウントイン（1小節）。
   - 入力: Space キー、画面のタップ領域（大きなボタン）、`pointerdown`。時刻には `event.timeStamp` を使う。
   - 結果: 各マスの上に打点を小さな印で重ね、早い・遅いを色と記号で示す。平均のずれと標準偏差を数値で表示する（**客観的な指標**）。
   - クリックの減らし方の練習: 4拍 → 2・4拍 → 1拍目 → なし。

## UI・UX 要件
- 開始後は、タップ以外の操作を必要としない。
- 結果は、ずれの数値だけでなく「全体に 18 ms 早い（走りぎみ）」のように言葉でも示す。

## 音声認識との連携要件
- 今回は音声を使わない（P12 で追加する）。
- 将来オンセットの入力に差し替えられるように、判定関数は「打点の時刻（performance の時刻）の配列」だけを受け取る形にする。

## 音楽理論・リズムの検証事項
- 120 BPM・16分音符の間隔が 125 ms になる。窓（±70 ms）が隣の予定と重ならないことを確認する。重なる場合は、窓を間隔の半分未満に自動で縮める。
- スウィング 67% で、8分の裏拍が拍の 2/3 の位置にくる。
- 3連の間隔が拍の 1/3 になる。

## テスト
- `expectedOnsets`、`judgeHits`（境界、余分、抜け、順序の保持）、`summary`、補正の外れ値の除外。
- 合成したタップ列（予定時刻＋既知のずれ＋揺れ）で、分類と統計が仕様どおりになる。
