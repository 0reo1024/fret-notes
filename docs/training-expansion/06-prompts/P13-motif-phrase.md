# P13 モチーフ・フレーズ構築と制約付き即興

あなたは Fret Notes（Tauri 2 + TypeScript + Rust）の開発を担当します。今回は進行トレーナーに「フレーズ」を追加し、短いモチーフの発展、コール＆レスポンス、制約付きの即興を練習できるようにします。**音楽性を点数にしない**ことが最重要の方針です。

## 目的
- 仕様は `docs/training-expansion/03-feature-specs.md` の §3.9、`07-proposals.md` の P-3（制約付き即興カード）と P-7（音高と時刻だけで記録する）。
- 判定を2種類に分ける。
  - 客観的に判定できる課題: 反復、移して反復。
  - 自己評価の課題: リズムの変形、休符・音価の工夫、コール＆レスポンス、自由な発展。

## 最初に確認すること（既存コード）

- P2 の `NoteSegmenter`。P12 のオンセット（ある場合は、連打と音価を記録に反映できる）。
- P10 の `generateMelody`。P11 のリズムの変形（1拍ずらす、倍、半分）。

## 変更対象と要件
1. ドメイン（新規・提案名 `src/domain/training/motif.ts`）
   - `Motif {notes: {midi, beats}[], startBeat}`、`contour(motif)`（隣り合う音の音程の列）。
   - 客観的な判定
     - `matchesRepeat(events, motif)`: 同じ MIDI の列（またはオプションで音高クラス）。
     - `matchesTransposed(events, motif, startPitchClass)`: 輪郭が一致し、開始音が指定の音高クラス。
     - 判定は音高の列だけで行う。リズムは P12 のオンセットがある場合に参考として示す。
   - 参考指標（**点数ではない**）: 音の数、使った音高の種類、休符の割合（無音の時間 ÷ 全体）、コードが変わった直後の着地の度数（P8 の `landingDegree`）、モチーフとの輪郭の類似度（参考）。
   - 課題カードの生成: 種類 × 進行 × モチーフ。制約カード（P-3）の例は「3音だけ」「1弦だけ」「休符で始める」「8分音符だけ」「各小節の頭は 3rd」。
2. 画面（進行タブのサブタブ「フレーズ」）
   - 課題カード、モチーフの再生ボタン（合成音）、開始（自動進行。P8 の部品）。
   - 演奏の記録: `NoteEvent` の列を時間軸上に音名で表示し、「自分の演奏を再生」（合成音）できるようにする。
   - 自己評価のチェックリスト（はい／一部／いいえ）
     - 「モチーフが聞き取れる形で残っていたか」
     - 「休符で間を作れたか」
     - 「コードの変わり目を意識できたか」
     - 「制約を守れたか」
     - 任意のメモ（最大200文字）
   - 保存: `PhraseTake` を `takes` に直近20件まで残す。記録には `self-marked` として保存し、間隔反復には使わない。
   - 制約カード（P-3）は、記録なしで使える「カードを引く」ボタンでも提供する。
3. 「一弦だけ」などの制約の扱い
   - 演奏では弦を判定できない。このため、自己評価の項目にする。
   - 音域で判定できる制約（「5〜7F」→ 音域の窓）は、参考指標として「窓の外の音が N 回」と表示してよい。

## UI・UX 要件
- 「採点しない」ことを画面に明記する。参考指標は控えめに表示する。
- 録音（音声）は行わない。そのことを画面に1行書く（「演奏は音高と時刻だけを記録します」）。

## 音声認識との連携要件
- 記録は `NoteSegmenter` のイベントだけにする。オンセット（P12）がない場合、同じ音の連打は1つにまとまる。そのことを説明に書く。

## 音楽理論の検証事項
- 輪郭の一致: モチーフ C–D–E（+2, +2）を F から移した F–G–A は一致する。F–G–A♭（+2, +1）は一致しない。
- 調の中で移す（ダイアトニックの移動、例: C–D–E → D–E–F）は、輪郭が半音単位で変わる。このため「調の中で移す」オプションを別に用意し、度数の輪郭（音階上の段数）で比べる。
