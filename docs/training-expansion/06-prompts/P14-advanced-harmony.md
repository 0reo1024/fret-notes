あなたは Fret Notes（Tauri 2 + TypeScript + Rust）の開発を担当します。今回は上級者向けに、テンション・アヴォイドノート・アプローチノート・エンクロージャー・ビバップスケール・オルタードなどを、**既存のトレーナーに出題の種類とカタログを追加する形で**実装します。新しい画面は作りません。

## 目的
- 仕様は `docs/training-expansion/03-feature-specs.md` の §3.10、`04-architecture.md` の §4.6.1（L7）。
- 前提の練習が定着してから開放する。ただし「すべて表示」でいつでも使えるようにする。

## 変更対象と要件
1. カタログの追加（2つの案から、確認したうえで選ぶ）
   - **案A**: `theory.ts` の `chords` / `scales` に直接追加する。
     - 指板学習の表示にも追加される（利点）。
     - 既存のテストの一致の確認と、シェイプの空の表示を確かめる必要がある。
   - **案B**: 上級のカタログを別の配列（新規・提案名 `src/domain/music/advanced.ts`）に置き、トレーナーだけで使う。
   - 推奨は案A。ただし `migration.test.ts` が全カタログの一致を前提にしている場合は、「既存の19品質と21スケールが旧版と一致する」形にテストを絞る。テストを削除せずに範囲を明示する。
   - 追加する品質（`group: 'テンション'`）
     - 7♭9（R 3 5 ♭7 ♭9）
     - 7♯9（R 3 5 ♭7 ♯9）
     - 7♯11（R 3 5 ♭7 9 ♯11）
     - 13（R 3 5 ♭7 9 13）
     - 7♭13（R 3 5 ♭7 ♭13）
     - m11（R ♭3 5 ♭7 9 11）
     - maj7♯11（R 3 5 7 9 ♯11）
     - 6/9（R 3 5 6 9）
   - 7alt は品質として追加しない。コード・スケールの文脈（オルタードスケール）で扱う。
   - 追加するスケール
     - ドミナント・ビバップ（R 2 3 4 5 6 ♭7 7）
     - メジャー・ビバップ（R 2 3 4 5 ♯5 6 7）
     - 既存のメロディックマイナーのモード（リディアン・ドミナント、オルタード、ロクリアン♮2、リディアン・オーギュメント）はそのまま使う。
   - Rust 側の検証（`storage.rs` の `studyChord` などの許可リスト）がある場合は、追加した id を許可する。
2. 出題の種類の追加
   - ハーモニー・トレーナー
     - 「テンション」: G7♭9 の ♭9 は? → A♭。
     - 「コード・スケール」: G7alt に使うスケールは? → G オルタード（A♭ メロディックマイナーの第7モード）。Cmaj7♯11 → C リディアン。Dm7（ii）→ D ドリアン。
   - 進行トレーナー
     - 段階「アプローチ」: 各コードの 3rd（または指定の度数）へ、パターンの3音（または2音）で到達する。
     - パターン
       - 下からの半音
       - 上からの全音階音
       - 二重の半音
       - エンクロージャー（上の全音階音＋下の半音）
       - エンクロージャー（上の半音＋下の半音）
     - 判定には P2 の `SequenceTracker` の順番ありを使う。
   - ライン（P9）: 許可する度数に「テンション（9th・13th）」を追加するオプション。
3. アヴォイドノートの表示
   - 次のものを「文脈に依存するガイド」として表示する。
     - アイオニアンの4th（11）
     - ミクソリディアンの4th（11）
     - フリジアンの♭9
     - エオリアンの♭13
     - ロクリアンの♭9
   - **誤答とはしない。**
   - ドリアンの13（6th）は流派によって扱いが異なる、と注記する（既定では表示しない）。
   - 採用した定義の方針を説明文に書く。
4. 段階的な開放
   - L7 の項目は、L4（ガイドトーン）の項目の80%以上が `isMastered` になると開放する。
   - 「すべて表示」のスイッチ（preferences に保存）で、いつでも開放できるようにする。
   - 開放の状態は記録タブにも表示する。

## 音楽理論の検証事項（テストで確認する）
- 追加した品質 × 標準12ルートの綴りが、手書きの正解表と一致する。
  - 例: C7♯9 = C E G B♭ D♯、F13 = F A C E♭ G D、B♭7♭9 = B♭ D F A♭ C♭、E♭maj7♯11 = E♭ G B♭ D F A。
- ♯11 と ♭5、♭13 と ♯5、♯9 と ♭3 が、異なる度数として綴られる。
- エンクロージャー: Cmaj7 の 3rd(E) に向けて、上の全音階音 F、下の半音 D♯、到達 E。下の半音は E♭ ではなく D♯ と綴る（目標の音への導音として）。
- ドミナント・ビバップ（G）: G A B C D E F F♯。
- 既存の19品質と21スケールの結果が変わらない。

## 共通ルール（必ず守ること）
- 作業前に CLAUDE.md、docs/training-expansion/ の該当節、docs/migration-progress.md を読む。仕様と実際のコードが食い違う場合は、コードを確認したうえで食い違いを報告し、既存の挙動を壊さない側を選ぶ。
- 既存の機能を削除・変更しない（このプロンプトで明示した変更を除く）。既存のテストを削除しない。
- 新しいライブラリ・外部API・クラウドサービスを追加しない。src-tauri/tauri.conf.json の CSP（connect-src）を広げない。
- 音声データを保存・送信しない。テスト用のフィクスチャは解析結果（時刻・状態・周波数・レベル）だけにする。
- 音楽理論と判定のロジックは、DOM に依存しない src/domain/ に置き、tests/*.test.ts（node --test、tsx）で表を使ったテストを書く。
- ギター、4弦／5弦ベース、任意チューニングのすべてで動くようにする。単音認識しかできない前提を守り、和音認識を前提にしない。
- 新しいファイルの書き方は src/domain/practice/performance.ts に合わせる。既存ファイルを整形し直さない。不必要な大規模リファクタリングをしない。
- 完了時:
  1) npm.cmd test、npm.cmd run typecheck、cargo test --manifest-path src-tauri/Cargo.toml --lib をすべて成功させる。
  2) 開発プレビュー（.claude/launch.json の web）で、新機能と既存の3機能（指板学習・チューナー・演奏練習）を操作して確認する。
  3) docs/migration-progress.md と README.md を更新する。実装したこと、検証したこと、未検証のことを分けて書く。
  4) 版を上げる場合は package.json、src-tauri/tauri.conf.json、src-tauri/Cargo.toml を揃える。installer/fret-notes.iss の AppId は変更しない。
  5) 最後に npm.cmd run desktop:install を実行する。
- git のコミット・プッシュは、利用者の指示があるまで行わない。
