# Fret Notes 機能拡張計画 — 即興演奏トレーニングへの拡張

作成日: 2026-10-26 ／ 対象の版: 0.4.0（作業ツリーの現状）／ 状態: 設計のみ（アプリのコードは変更していない）

## 目的

Fret Notes を、複雑なコード進行の上でも音楽的に自由なアドリブができる力を育てる総合トレーニングアプリへ拡張します。

この計画で目指す学習の流れは、次の段階を経て、最後は意識的に計算せずに即興の中で自然に弾けるようになることです。

1. G7 を見る。
2. 3rd が B だと分かる。
3. 指板上の B を見つける。
4. 実際に弾く。
5. 次の Cmaj7 の E へ滑らかにつなぐ。

この流れを、**知識・指板・演奏の3つの層**で測り、つなげていく設計にしています。

## 要点

### 1. 現状（コードで確認した事実）

- 音声エンジンは**単音の YIN**。
  - 約15 Hz で通知し、stable になるまで約200〜450 ms かかる。
  - **和音・オンセット・同音の再アタックは検出できない。**
- 判定（`PerformanceSession`）は1つの MIDI だけを目標にする。
- 練習の結果は保存していない。
- 音を出す仕組み（Web Audio）はない。
- 設定ファイルは厳格なスキーマ（v3）で、`profiles` の `mode` も Rust が検証している。

### 2. 機能構成

依頼の11機能を、5つの練習と3つの共通基盤にまとめる。

- 練習: 指板、ハーモニー、進行、耳・リズム、記録
- 共通基盤: 和声エンジン、matcher、記録ストア

### 3. 最重要の機能

3rd/7th の瞬間回答（P5）。共通基盤（P1〜P3）の直後に実装する。

### 4. 音声の制約を設計に反映した点

| 制約 | 設計での扱い |
| --- | --- |
| リズムの判定 | 先にタップ入力で行い、オンセット検出（Rust）を後から追加する |
| 自動進行 | 判定窓を広くし、短すぎるコードは選べないようにする |
| 聴音 | 再生中は判定しない（半二重）。同じ音の連続は出題しない |
| 位置の制約 | 演奏では弦を判定できないため、音域の窓で代用し、そのことを画面に明記する |
| 誤判定への対策 | 検出の失敗を誤答と区別して記録する。スキップと自己判定をいつでも選べる |

### 5. 音楽性は点数にしない

モチーフ・自由な即興は、自己評価と参考指標（着地の度数など）で扱う。

### 6. プライバシー

- 音声を録音しない。演奏の記録は音高と時刻だけにする。
- 外部への通信を追加しない。
- 学習記録は、端末のローカルにある別ファイル `training-data.json` に保存する。

## 未確認・判断が必要な事項

- 既存の演奏判定の実機での精度（ベースの低音を含む）は、版 0.4.0 の時点で未確認。最初に P0 で確認することを推奨する。
- 「演奏練習」タブを指板学習へ統合するかどうか（Part 7 §7.2.1）。
- 15F以上への指板の拡張（§7.2.2）。
- スマートフォン・タブレット版（§7.2.3）。
- 機能（T/SD/D）の分類と、アヴォイドノートの定義は流派によって差がある。アプリとして採用する定義（Part 3 §3.10）を、最終的に利用者が確認する。
